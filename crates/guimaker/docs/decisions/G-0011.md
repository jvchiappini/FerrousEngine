# G-0011 - Main-window backend default (Vulkan vs DX12)

## Context

Phase 9B compared GUIMaker's startup with egui (255.9 ms median to first frame)
and measured GUIMaker at 560.9 ms. G-0010 had measured a DX12 popup surface at
36 ms against 61-64 ms on Vulkan, which suggested DX12 might be the faster
main-window backend. The question is whether the whole main-window startup
(instance, adapter, device, surface, renderer, first frame) is faster on DX12.

The GPU probe (instance + surface-less adapter) already runs on a worker while
winit creates the window (S3). The trace below confirms the overlap: the window
exists at 19.22 ms and the worker reports the instance at 207.10 ms.

## Measurements

Release build, `guimaker-compare-guimaker` (start screen, 1280x800, Flat2D,
vsync), RTX 4050 Laptop, Windows 11, one traced run per backend, marks in ms
from process entry:

| Phase | Vulkan | DX12 |
|---|---:|---:|
| window created | 19.22 | 18.34 |
| instance | 207.10 | 325.17 |
| adapter | 207.10 | 325.18 |
| device | 243.31 | 401.37 |
| surface configured | 426.53 (183.22 span) | 451.27 (49.90 span) |
| renderer built | 472.78 (46.25 span) | **7003.21 (6166.66 span)** |
| first frame presented | **477.39** | none before the 800 ms show timeout |
| teardown done | 2535.81 | 7035.81 |

The surface step is faster on DX12 (49.9 ms against 183.2 ms), but the renderer
build is **6166.7 ms** because the 2D pipeline set is rebuilt and wgpu 23's
pipeline cache is Vulkan-only (DX12 and Metal ignore it). A 7 s renderer is not
a viable main-window startup.

## Decision

**Vulkan remains the default main-window backend on Windows** (the existing
`AppConfig::backends` order: Vulkan, DX12, GL). DX12 stays selectable through
`WGPU_BACKEND=dx12` for the popup/low-pipeline experiments and for drivers where
Vulkan is broken. The backend order is not changed by Phase 9B.

The worker-thread instance/adapter overlap is kept and is verified: the window
is created 188 ms before the instance mark, so the two are not serialised.

## Consequences

- GUIMaker's 560.9 ms first frame is the Vulkan driver floor plus renderer, not
  a missing overlap. The measured floor is 438-484 ms (S6); it cannot beat
  egui/glow's 255.9 ms on this machine, but it beats egui/wgpu's 837.3 ms.
- A future DX12 default would need the 2D pipeline build cut (a DX12 pipeline
  cache or a smaller pipeline set) before it can be reconsidered; that is
  outside Phase 9B.
- `G-0010`'s DX12 surface numbers stand for **popups** (no 2D pipelines); they
  are not a main-window startup result.

## Alternatives rejected

- **DX12 default:** renderer build 6166.66 ms vs 46.25 ms on Vulkan.
- **GL default:** the GL adapter lacks the texture-binding-array features the
  GUI image path needs; it is skipped with a warning.
- **Show the window before the first frame to quote a smaller number:** the
  runner already shows it when the first frame is ready (`show_window_when_ready`)
  or at the timeout with the background colour; the first-frame metric used in
  the comparison is the presented frame, so this would only change what is
  measured, not what the user sees.
