# G-0013 - One default backend per OS, chosen by measurement

## Context

G-0012 called GL a "hard floor" and closed DX12 before lazy pipelines existed.
Both claims were written before the alternatives were built:

- GL was rejected because the GUI image path asks for
  `TEXTURE_BINDING_ARRAY | SAMPLED_TEXTURE_AND_STORAGE_BUFFER_ARRAY_NON_UNIFORM_INDEXING`.
  That is **our** adapter requirement, held in `ENGINE_ADAPTER_FEATURES`
  (`crates/ferrous_engine/src/graphics.rs:175-183`), not a property of GL. Lane A
  is making the requirement optional.
- DX12 was rejected at 7.3-9.6 s `Renderer::new` (`G-0011`, `G-0012`), but the
  cost is the **eager** 2-D pipeline set: two `Renderer2d` instances built on the
  first frame with public, non-optional pipeline fields. Lazy pipelines are a
  known, scoped refactor (`out/reports/phase15/p9c-lane-b-notes.md`), not a
  permanent DX12 limit.

Phase 9D compares the backends again, per OS, and records the decision here.
The user's decision for this phase is explicit: **do not** build or investigate
runtime backend switching, a CPU-rendered first frame, or a cached per-machine
backend choice. Pick one default backend per OS, by measurement, and prove the
chosen backend is efficient.

## What counts as a floor

A backend is not a floor until the alternative that would make it competitive
has been built and measured:

- **DX12:** lazy / worker-compiled 2-D pipelines (or a DX12 pipeline cache).
  Without them, `Renderer::new` rebuilds the whole 2-D set every launch.
- **GL:** the texture-binding-array requirement made optional, so the GUI image
  path no longer rejects the adapter.
- **DX12 (compiler):** DXC present next to the executable or on `PATH`, with the
  loaded-DLL proof recorded; otherwise a "DXC" run is an FXC run (`G-0012`).
- **Vulkan:** warm and cold runs distinguished, because wgpu 23's pipeline cache
  is Vulkan-only and records the cold-build cost inside `Renderer::new`.

A candidate that loses only because one of these was not built is **unproven**,
not rejected. It is marked UNMEASURED in this document.

## Measurements

Scenario for every number below: release build,
`guimaker-compare-guimaker` (start screen + bench strip, 1280x800 logical,
Flat2D, vsync), RTX 4050 Laptop, Windows 11, marks in ms from process entry.
Five runs per backend, alternating cold/warm; cold means a fresh pipeline-cache
directory under `out/`, warm is the immediately repeated launch with the same
binary. The recipe is in `crates/ferrous_engine/docs/startup.md` under
"Measuring the per-backend startup breakdown".

**The Windows table below is filled by the main agent.** Final numbers live in
`out/reports/` and `bench/guimaker_compare/results/MEASURED.md`; this document
only fixes the decision structure and the candidate set.

| Windows phase | Vulkan | DX12 (lazy, DXC) | GL (optional bindless) |
|---|---:|---:|---:|
| window created | known (G-0011/G-0012) | pending | pending |
| instance | known | pending | pending |
| device | known | pending | pending |
| surface configured | known | pending | pending |
| renderer built (cold) | prior (9C) | pending | pending |
| renderer built (warm) | prior (9C) | pending | pending |
| first frame presented | prior (9C) | pending | pending |
| steady-state frame time | pending | pending | pending |

Known Phase 9C facts, used only as priors until the table above is filled:

- Vulkan is the current default and the only backend under 0.5 s to first frame
  (498.18 ms, G-0012).
- DX12's surface is 3.7x faster (50.6 ms vs 188.4 ms) but the eager renderer
  build is 7.3 s with DXC / 9.6 s with FXC, so the surface saving is 11 % of the
  renderer cost.
- GL has no measured number because it is rejected by our adapter check, not by
  the backend.

## Decision

### Windows

One Flat2D default and one 3-D default, both set to the **measured winner** in
the table above. The selection logic is explicit so the default is not a
re-derivation each time:

1. Vulkan wins if its first frame stays fastest across five alternating cold
   and warm runs **and** its steady-state frame time is within noise of the best
   candidate.
2. DX12 wins only after lazy 2-D pipelines exist and its measured first frame
   beats Vulkan's, with the DXC-loaded proof recorded. A fast surface alone is
   not enough while the renderer build dominates.
3. GL wins only after the texture-binding-array requirement is optional and its
   measured first frame and steady state beat the other two on the reference
   machine.
4. If Flat2D and 3-D pick different winners, both are recorded and set through
   `flat2d_backends()` and `default_backends()` in
   `crates/ferrous_engine/src/builder.rs`; there is no runtime switch.

Until the main agent records a winner, the order stays Vulkan, DX12, GL, so the
observed default does not change. The switch point is marked
`// Phase 9D: set to the measured winner (G-0013)`.

### macOS / iOS - Metal

The only first-class wgpu backend on Apple platforms. Vulkan is not native
(only through MoltenVK, which this engine does not ship), and OpenGL is
deprecated on macOS. Metal is the default, with no fallback list. **UNMEASURED
on this host.**

### Linux - Vulkan, with GL as fallback

Vulkan is the native path and wgpu's best-supported Linux backend; GL stays as
a fallback for stacks without a usable Vulkan driver. The order is Vulkan, then
GL. **UNMEASURED on this host.**

### Android - Vulkan, with GLES as fallback

Vulkan on modern devices, GLES for older ones and emulators. The order is
Vulkan, then GL. **UNMEASURED on this host.**

### Web - WebGPU, with WebGL2 as fallback

The browser chooses the backend. The engine asks for `BROWSER_WEBGPU` and falls
back to WebGL2 when WebGPU is absent or the origin is insecure
(`graphics.rs:624-641`). **UNMEASURED on this host** (requires a browser run).

## Consequences

- The default is one string list per OS, not a runtime policy. No probing other
  backends on a machine that already picked one, no per-machine cache, no
  CPU-rendered first frame.
- Changing the winner is a single edit in `builder.rs`; the decision record and
  `MEASURED.md` are the evidence, not the code comment alone.
- "Beats" means the whole measured path (cold and warm renderer build, first
  frame, steady-state frame time), not one phase. A faster surface with a slower
  pipeline build does not win.
- The `G-0011`/`G-0012` renderer numbers stay valid only for the **eager**
  pipeline set. Once lazy pipelines land, DX12 must be re-measured before it can
  be cited as slower.

## Alternatives rejected

- **Runtime backend switching:** the user rejected it for Phase 9D; one default
  per OS is simpler and measurable.
- **CPU-rendered first frame:** rejected; it changes what the first-frame metric
  means instead of making the GPU path faster.
- **Cached per-machine backend choice:** rejected; it makes the default
  machine-dependent and unverifiable.
- **Treating GL as a permanent floor:** rejected. The bindless requirement is
  ours and is being made optional.
- **Closing DX12 before lazy pipelines:** rejected. The 7.3 s cost is the eager
  pipeline set, not the backend.
