# G-0012 - Flat2D Windows backend and DX12 compiler

## Context

G-0011 kept Vulkan as the Windows default after measuring the DX12 renderer
build at 6166.7 ms (FXC). Phase 9C asked whether DX12 with DXC, or the GL
backend, can beat that for a Flat2D UI app, and whether the default should
differ from the 3D default.

The engine now exposes `AppConfig::dx12_compiler` and
`FERROUS_DX12_COMPILER=fxc|dxc|dynamic_dxc`; the instance is created with
`InstanceDescriptor::dx12_shader_compiler`. wgpu 23 has no `dxc` cargo feature:
DXC is loaded at runtime (`dynamic_dxc`), and the `dxc` feature on
`ferrous_engine` is a marker so a build can opt into the dynamic compiler.

## Measurements

Release, `guimaker-compare-guimaker` (start screen + bench strip, 1280x800
logical, Flat2D, vsync), RTX 4050 Laptop, Windows 11, one traced run per
backend, marks in ms from process entry. DX12 runs use `--seconds 15` because
the renderer build is longer than the 3 s bench watchdog.

| Phase | Vulkan | DX12 FXC | DX12 DXC |
|---|---:|---:|---:|
| window created | 20.38 | 25.72 | 19.67 |
| instance | 213.28 | 298.01 | 300.78 |
| device | 256.61 | 334.52 | 339.37 |
| surface configured | 445.03 (188.43 span) | 385.06 (50.55 span) | 390.64 (51.28 span) |
| renderer built | **491.99 (46.96 span)** | **9578.36 (8739.53 span)** | **7323.19 (6490.59 span)** |
| first frame presented | **498.18** | 9603.46 | 7346.21 |

DXC cuts the DX12 renderer build by **2255.2 ms (-23.5 %)** but it is still
**7.32 s**, 155x the Vulkan renderer build. The DX12 surface is 3.7x faster
(50.6 vs 188.4 ms), but it is 11 % of the DX12 renderer cost.

GL: `WGPU_BACKEND=gl` is rejected before the first frame:

`no usable wgpu adapter: every configured backend either had no adapter or
lacks Features(TEXTURE_BINDING_ARRAY | SAMPLED_TEXTURE_AND_STORAGE_BUFFER_ARRAY_NON_UNIFORM_INDEXING)`

The engine's GUI image path requires those features; wgpu 23's WGL adapter does
not offer them. This is a hard floor for GL in this engine, not a tuning issue.

Lazy 2D pipelines: the blocker is recorded in
`out/reports/phase15/p9c-lane-b-notes.md` (two eager `Renderer2d` instances,
public non-optional pipeline fields at 19/62 call sites, and
`renderer_core.rs:3151` forcing `renderer_2d_pure` on the first frame). Not
implemented in Phase 9C.

## Decision

- **Vulkan stays the Flat2D Windows default.** The backend order is unchanged
  (Vulkan, DX12, GL). DX12 is selectable with `WGPU_BACKEND=dx12`; DXC with
  `FERROUS_DX12_COMPILER=dynamic_dxc`.
- **The Flat2D default does not differ from the 3D default.** The DX12 renderer
  build is the blocker on both; Vulkan is the only backend under 0.5 s.
- **GL is not a candidate on this engine** until the GUI image path can work
  without the texture-binding-array features (or a GLES/ANGLE path is added).

## Consequences

- A future DX12 default needs the 2D pipeline set cut (lazy/worker compilation
  or a DX12 pipeline cache), not a compiler change. DXC alone leaves 7.3 s.
- The startup floor for a Flat2D app on this machine is the Vulkan instance +
  surface (~390 ms) plus the renderer (~47 ms); G-0011's 438-484 ms driver floor
  stands.
- `dxcompiler.dll` must be next to the executable or on `PATH` for
  `dynamic_dxc`; otherwise wgpu falls back to FXC (and the 9.6 s renderer).

## Alternatives rejected

- **DX12 DXC as the Flat2D default:** first frame 7346.21 ms vs 498.18 ms.
- **GL:** no usable adapter with the required features.
- **DXC with the static compiler:** wgpu 23 does not expose a static DXC
  feature; the runtime DLL is the only path.
