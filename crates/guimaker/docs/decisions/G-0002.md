# G-0002 — Typefaces and densities

## Context

D-0021 shipped a single Roboto weight and produced a medium weight by drawing
the same text twice with a small offset. The result is not a typeface: the
metrics stay those of the regular weight, the glyphs thicken on the edges
rather than through their stem, and every label is painted with two draw
passes. The design system this library has to carry needs real weights, and
it needs them at the sizes a dense editor actually uses.

The type roles are Display, Title, Heading, Subheading, Body, BodyStrong,
Label, Caption, Overline, Mono and Code. Two densities are in scope from the
start: Compact, for editors that pack many controls per unit of area, and
Comfortable, for launchers and settings.

G-0001 §3 already commits the headless tests to a metrics table generated
from the real Inter files, so the family is assumed before this document
exists. This decision fixes which faces, which names, and what the licence
permits.

## Decision

Ship the **Inter** family, under the SIL Open Font License 1.1, with real
Regular (400), Medium (500), SemiBold (600) and Bold (700) static faces. Ship
**JetBrains Mono**, also under the SIL OFL 1.1, in Regular (400) and Medium
(500) for the Mono and Code roles.

The library exposes the families by name:

```text
SANS_FAMILY = "Inter"
MONO_FAMILY = "JetBrains Mono"
```

Every place that faked a bolder weight with a two-pass draw is deleted once a
real face exists for that weight. The faux-bold trick survives only where no
real weight is defined, and none of the roles above need it.

Tabular numerals are required for numeric UI — timecode, inspector fields and
rulers — and Inter provides them. Type roles that show numbers request the
tabular variant rather than relying on the proportional default.

Fonts are assets, not a Rust dependency. `guimaker_ferrous` ships them in
phase 5; the core only names families and weights and never links a font
file. The exact vendored file sizes are measured when the assets land in
phase 5 and recorded here then; this document does not guess at them.

Licence obligations, recorded now: the OFL permits bundling and embedding the
fonts in an application. The fonts are not renamed, and the licence files
ship next to the font files in the asset bundle.

## Consequences

- The theme expresses a real weight ramp: 400, 500, 600 and 700 for sans and
  400 and 500 for mono, instead of one weight plus an offset copy.
- The adapter loads four sans faces and two mono faces and registers them
  with the text system.
- Binary size grows by the font assets. The exact number is measured in
  phase 5, not asserted here.
- The faux-bold code paths are removed from the adapter and the palette.

## Alternatives rejected

- **Keep the single Roboto weight with the faux medium.** Wrong metrics, two
  draw passes per label, and no semi-bold at all — the weight ramp the type
  roles assume cannot be built on it.
- **System UI fonts.** They are different on every machine, which breaks the
  byte-identical screenshot guarantee G-0001 §2 and §4 rely on.
- **Geist.** Viable, but Inter is already the content font in D-0034, so one
  family serves both chrome and content and the metrics table is shared.
