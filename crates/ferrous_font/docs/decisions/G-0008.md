# G-0008: bidi reordering and Arabic joining are deferred

- Status: accepted, deferred
- Date: 2026-11-23

The review requires minimal UAX #9 run reordering (paragraph level, logical
caret/selection) and Arabic joining through GSUB `init`/`medi`/`fina`/`isol`,
with the logical-order string.

`ferrous_font` parses `kern` and GPOS and has no GSUB feature lookup, and the
shaper is per-character with no bidi resolution. Implementing both is a shaping
rewrite (paragraph level detection, run segmentation, visual reordering that
keeps byte ranges logical, GSUB feature application per joining class), not a
patch; it is scheduled for the text phase after 8B.

The gap is explicit, not hidden: `guimaker_ferrous::text::tests::
arabic_is_drawn_in_isolated_visual_order` asserts the current behaviour (one
glyph per character, no joined forms, the string drawn in the given order) so
the day the shaper changes, the test fails and must be replaced with the joined
expectation. The mixed-script pixel test keeps the logical string and checks
glyph coverage only, never claiming shaping.
