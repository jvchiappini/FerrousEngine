# G-0007: face metrics are already normalised to em

- Status: accepted (no code change)
- Date: 2026-11-23

`FontParser` divides every face's hmtx advance, glyf bounds, kern/GPOS value and
the `hhea`/`head` font metrics by **that face's** `units_per_em`
(`crates/ferrous_font/src/parser.rs:1327`, `:1352`, `:675`, `:647`). `LayoutData`
therefore holds advances and bounds in em, and `layout` only multiplies them by
the point size. A mixed atlas does not mix units.

The review asked to normalise every fallback face into the primary face's units
and to test a face whose `units_per_em` differs. `tests/units_per_em.rs` finds a
system `glyf` face with a different `units_per_em` (Dubai, 1000, on the reference
machine), asserts its advance is identical in the parser and in `LayoutData`,
that it is in em (0.05..2.0), and that `build_multi` copies that em advance into
the composite atlas unchanged. No per-glyph scale is needed; adding one would
double-normalise.

If a future parser stops normalising, this test fails first.
